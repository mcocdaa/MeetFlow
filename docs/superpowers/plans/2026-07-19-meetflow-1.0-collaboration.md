# MeetFlow 1.0 Collaboration and Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add trustworthy multi-user discussion, activity history, direct notifications, and a polling inbox without turning shared activity into notification noise.

**Architecture:** Record immutable activity events inside the same transaction as domain writes. Comments form shallow reply threads on five supported target types. A notification projector creates idempotent direct notifications for mentions, replies, review requests, assignments, and due alerts; the existing attention service coalesces those reasons per subject. The browser polls a cursor endpoint every 25 seconds, throttles hidden tabs, and refreshes on focus.

**Tech Stack:** FastAPI, SQLAlchemy 2, SQLite, Pydantic 2, pytest, Vue 3, TypeScript, Vitest, Testing Library

- [ ] **Step 3: Implement notification identity and projection**

Create `Notification` with recipient, kind, subject, actor, event ID, reason, href, read/dismiss timestamps, and created time. Add unique `(user_id, dedupe_key)`. Project only direct reasons: mention/reply; action assignment/due/overdue; host/recorder/presenter assignment; decision review request; participating-meeting cancellation, reschedule, or reopen; and the submitter's AI job success/failure. Ordinary edits and uploads remain only in activity feeds.

- [ ] **Step 4: Expose cursor and state commands**

```text
GET  /api/inbox?after={created_at,id}&limit=50
GET  /api/inbox/changes?cursor={last_event_id}
POST /api/inbox/{id}/read
POST /api/inbox/read-all
POST /api/inbox/{id}/dismiss
GET  /api/inbox/unread-count
```

The history list encodes its cursor from `(created_at, id)` so equal timestamps do not skip rows. The changes endpoint uses a monotonic event cursor and returns `next_cursor`, unread count, new/changed notifications, and changed attention subject IDs. State commands require ownership and are idempotent.

- [ ] **Step 3: Implement focus-aware polling**

Changes and inbox history keep independent server cursors.
