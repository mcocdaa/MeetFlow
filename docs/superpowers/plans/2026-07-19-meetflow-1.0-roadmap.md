# MeetFlow 1.0 Implementation Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved MeetFlow 1.0 design through five ordered, independently testable implementation plans.

**Architecture:** Keep a single-container modular monolith. Build the new relational domain first, then the workspace UI, collaboration/inbox, trusted plugin jobs, and final release hardening. Every plan leaves the implemented scope runnable and tested.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2, Alembic, SQLite, Vue 3, TypeScript, Milkdown 7.21, Vitest, Docker Compose

## Design traceability

| Approved design area | Owning plan |
| --- | --- |
| Projects, updates, series, occurrences, agenda, outcomes, snapshots, amendments, files | Core domain |
| “For you”, project/meeting information architecture, Milkdown, conflict recovery | Workspace UI |
| Activity, comments, direct notifications, attention dedupe, incremental polling | Collaboration and inbox |
| Fixed trusted plugins, encrypted independent config, text-only actions, persistent jobs | Plugin jobs |
| Security/recovery checks, exports, Docker, CI, deployment and end-to-end acceptance | Release and acceptance |

Authentication, registration approval, sessions, and the single shared workspace remain supported foundations. Core-domain migration tests preserve their tables; the final acceptance flow re-verifies admin approval and ordinary-member access after the fresh 1.0 baseline.

## Checkpoint contracts

### Checkpoint 1: Core domain

Produces:

- Fresh Alembic baseline.
- Projects, memberships, meeting series, occurrences, participants, and agendas.
- Decisions, action items, open questions, snapshots, amendments, lifecycle commands, and optimistic versions.
- Versioned JSON APIs that replace the v0.1 meeting-package API.

Acceptance:

```bash
python -m pytest backend/tests/domain backend/tests/api -q
python -m alembic -c backend/alembic.ini upgrade head
```

### Checkpoint 2: Workspace UI

Produces:

- Stable authenticated application shell.
- Personal attention home, projects, meetings, decisions, and actions navigation.
- Project overview and lifecycle-aware meeting workspace.
- Right-side mutable agenda queue.
- Milkdown Markdown editor with conflict preservation.

Acceptance:

```bash
npm --prefix frontend test
npm --prefix frontend run build
```

### Checkpoint 3: Collaboration and inbox

Produces:

- Comments, replies, tombstones, and mentions on project/meeting/agenda/decision/action targets.
- Activity events, direct notifications, attention aggregation, and incremental polling.
- Inbox, comment threads, project activity, and unread badges.

Acceptance:

```bash
python -m pytest backend/tests/collaboration -q
npm --prefix frontend test -- collaboration inbox attention
```

### Checkpoint 4: Plugin jobs

Produces:

- Expandable plugin list with independent configuration.
- Desired/runtime state and restart-pending labels.
- Persistent SQLite plugin jobs with active-job deduplication.
- One in-process worker and simple text-generation results.
- AI task history, result editing, and explicit application.

Acceptance:

```bash
python -m pytest backend/tests/plugins -q
npm --prefix frontend test -- plugins jobs
```

### Checkpoint 5: Release

Produces:

- Updated exports, backup/restore, Docker, CI, documentation, accessibility, and complete acceptance tests.
- Fresh-data reset instructions; no v0.1 migration.
- A release candidate ready for a `v1.0.0` tag.

Acceptance:

```bash
python -m pytest -q
npm --prefix frontend test
npm --prefix frontend run build
docker compose build
docker compose up -d
```

## Cross-plan rules

- Follow red-green-refactor for every behavior change.
- Never silently delete a v0.1 database.
- Preserve one Uvicorn worker and one Docker container.
- Keep all state transitions in domain services and explicit command endpoints.
- Write activity events in the same transaction as their domain change once collaboration exists.
- Keep Markdown as the persisted long-form format.
- Keep plugin code trusted, fixed on disk, and loaded only at startup.
- Do not add ToolCall, autonomous research, browser automation, or Agent terminology.
- Do not auto-apply AI output.
- Run `git diff --check` before every commit.

## Final release gate
