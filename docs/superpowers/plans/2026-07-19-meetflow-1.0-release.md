# MeetFlow 1.0 Release and Acceptance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish MeetFlow 1.0 as one reproducible, low-memory Docker deployment with export, backup/restore, CI packaging, operational documentation, and full workflow acceptance.

**Architecture:** The production image builds Vue assets first, then copies them into the Python runtime image. Startup performs the schema guard and Alembic migration before serving FastAPI, SQLite, uploads, and fixed plugins from one writable data volume plus one read-only plugin path. Release tests exercise the container as users do, not only individual modules.

**Tech Stack:** Docker/BuildKit, FastAPI, Vue/Vite, Alembic, SQLite, pytest, Vitest, Playwright or HTTP smoke tests, GitHub Actions, GHCR

- [ ] **Step 2: Implement online backup and offline restore**

- [ ] **Step 1: Write the container-startup acceptance test**

Build the image, start it with temporary data and plugin directories, wait on `/api/health`, then assert `/`, `/projects/demo`, `/assets/*`, `/api/openapi.json`, registration policy, and authenticated API requests work. Restart the same container volume and assert records persist and queued plugin jobs recover.

- [ ] **Step 2: Build a deterministic multi-stage image**

Node stage runs `npm ci` and `npm run build`. Python stage installs the locked project, copies backend, migrations, plugins, and `frontend/dist`, creates an unprivileged user, and sets `FRONTEND_DIST=/app/frontend/dist`. Do not include source `.env`, local databases, uploads, tests, `.git`, or `node_modules`.

- [ ] **Step 3: Make entrypoint fail clearly**

`docker-entrypoint.sh` verifies required admin credentials and writable data paths, runs the legacy schema guard and `alembic upgrade head`, then `exec`s one Uvicorn process. Do not run multiple workers because SQLite writes and the in-process plugin queue require single-process ownership.

Compose mounts `/data` writable and `/app/plugins` read-only, sets a memory limit below 2 GB, uses a healthcheck, `init: true`, and `restart: unless-stopped`. Document that changing plugin enabled state requires container restart.

`scripts/smoke.sh` starts the exact image, creates/admin-authenticates a project, meeting, agenda, outcome, comment, and plugin job with a fake disabled plugin, finishes the meeting, exports it, restarts, and confirms persistence. It always removes its temporary container and volume.
