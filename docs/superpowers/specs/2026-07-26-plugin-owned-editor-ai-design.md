# 插件化编辑器内 AI 建议

## 目标

把 AI 从独立的“待确认草稿”页面收回到用户正在编辑的位置。会议纪要、项目进展和行动项建议都在对应编辑器右上角由插件提供入口。用户在原位查看、编辑、撤销和保存结果；任务中心只用于追踪执行记录、重试和查看诊断。

这项改动还消除两项现有缺陷：任务完成后必须刷新才出现结果，以及失败的未应用任务无法丢弃。

## 范围与边界

### 核心服务和前端

核心保留以下通用能力：

- 管理员启用、配置和加载受信任的挂载插件；
- 为插件动作创建异步 `PluginJob`，制作目标对象和权限范围内的上下文快照；
- 运行、取消、重试、列出、应用状态变更和丢弃任务；
- 记录状态、结果和经过脱敏的错误诊断；
- 提供通用的编辑器插槽宿主以及任务中心的基础状态和诊断展示。

核心不得再知道 `ai-work-assistant.meeting_summary`、`project_progress` 或 `action_suggestions` 等特定动作 ID，也不得为某一 AI 插件决定按钮文案、草稿卡片、提示词或结果写入方式。

### 插件

插件拥有动作及其前端交互：

- 通过清单声明其可静态提供的前端模块；
- 前端模块注册自己支持的编辑器插槽和任务记录渲染器；
- 插件自行放置“AI 建议”按钮、生成覆盖层、局部错误提示、轮询和结果写回；
- 插件后端根据 `current_markdown` 和核心的上下文快照生成结果。

插件前端与 Python 后端具有同样的受信任边界：只有管理员挂载并启用的本地插件可被加载。核心只提供受限的静态文件路径，不接受网页上传的可执行插件代码。

## 前端扩展协议

每个启用插件可以在其目录中携带一个已构建的前端模块。模块由核心的通用宿主加载，并向注册表声明：

- 插槽名称，例如 `meeting-summary-editor`、`project-update-editor`、`action-composer`；
- 可渲染的 Vue 组件；
- 对应的插件动作 ID；
- 可选的任务中心详情组件。

宿主向插槽组件传入目标类型与 ID、当前编辑器值、更新编辑器值的回调、以及目标范围内的参与者等非敏感界面数据。提交任务时，插件前端必须把当前编辑器文本作为 `current_markdown` 传给动作；核心仍会在服务器端追加项目、会议、议题等权威上下文快照。

核心仅从已发现、已启用插件的指定前端目录提供文件，并拒绝路径穿越。运行时加载的代码属于管理员已审查的插件，不对普通成员开放安装或配置入口。

## 编辑器内交互

所有支持的编辑器使用相同状态机：

1. 空闲时，编辑器右上角显示插件定义的 `AI 建议` 控件。
2. 点击后，插件只创建一个任务；该控件禁用，编辑器只读并显示居中的半透明进度层。用户不离开当前页面，也不能再次提交或编辑同一份内容。
3. 任务成功时，插件以一次编辑器替换操作写入结果，解除只读和按钮禁用。用户可以继续人工修改，然后使用原有保存或发布动作提交业务数据。
4. 对 Markdown 编辑器，写回必须通过其 ProseMirror/Milkdown 历史事务完成；一次 Ctrl+Z 恢复生成前的完整内容，而非逐字符撤销。
5. 任务失败、取消或中断时，原始编辑内容绝不改变。编辑器立即解锁，顶部出现简洁的失败通知；用户可再次请求建议。

生成完成不自动保存会议、项目动态或行动项，避免 AI 结果覆盖用户未确认的数据。

## 三个首批插槽

### 会议纪要

会议工作区提供一个持续编辑的会议纪要 Markdown 编辑器。AI 插件将纪要结果直接写入此编辑器；用户可撤销、继续编辑，并通过正常的会议信息保存流程落库。

### 项目进展

项目动态编辑器使用具备历史记录的 Markdown 编辑器，而不是普通 textarea。AI 插件依据正在编辑的进展、项目状态、近期进展和相关决策润色或补全内容。用户确认后仍通过“发布进展”创建一条独立历史记录。

### 行动项建议

行动项编辑器中的 AI 建议不立即创建数据库行动项。成功时，插件在当前编辑器旁生成一组未保存、可编辑、可删除的临时行动项草稿；整组插入作为一次可撤销操作。用户可以逐条选择负责人、截止日期和优先级，随后通过现有创建动作显式入库。撤销或关闭编辑器会丢弃未保存草稿，不影响已存在行动项。

## 任务历史与错误

任务中心是通用历史页：显示插件、动作名称、目标、创建时间、状态、安全错误摘要和经脱敏的技术详情。插件可提供更具语义的任务结果预览，但核心不依赖该预览来处理状态或权限。

任何未应用的终态任务（成功、失败、取消或中断）都可丢弃。执行中的任务只能取消，不能伪装为已丢弃。列表轮询不得在排队阶段把空结果标记为已初始化；首次看到成功结果时必须把真实结果交给插件渲染器。

## 错误与可靠性

- API Key、Authorization 头和 JSON 中的密钥字段继续在持久化与界面前脱敏；
- 网络、认证、余额、限流、模型和输出错误保持机器可分类的错误码，以及面向用户的短消息；
- 前端请求失败不修改编辑器模型；
- 插件动作使用现有去重键，重复点击或并发提交不能产生多项等价任务；
- 插件不可用或未启用时，核心编辑器仍可正常编辑和保存，只是不显示该插件控件。

## 验收标准

1. AI 工作助手作为插件前端模块在三个插槽中显示自己的入口，核心页面不再导入 AI 专用草稿或动作面板组件。
2. 每个入口提交时携带当前编辑值，后台提示词同时收到该值和服务器端上下文快照。
3. 请求期间按钮不可重复点击、编辑器不可编辑并显示局部进度；完成或失败后均恢复空闲状态。
4. 成功写回一次 Ctrl+Z 可恢复原内容；失败时原内容完全不变。
5. 行动项建议只产生可编辑的临时草稿，用户确认前数据库中不新增行动项。
6. 无刷新轮询后成功结果立即显示；失败、取消或中断任务可以丢弃，详细错误仍可在任务中心查看。
7. 插件未启用、前端模块加载失败或任务接口出错时，不妨碍原有会议、项目和行动项编辑流程。
