# AI Star 编辑器交互与施工态设计

**日期：** 2026-07-29  
**范围：** 已注册 AI 编辑器助手的前端交互与视觉样式。  
**不在范围内：** AI 请求、任务轮询、结果写入和保存 API 的语义变更。

## 目标

让所有编辑器内 AI 操作拥有一致、克制且可理解的体验：

- Star 打开与当前编辑块相关的操作列表；
- 用户发起生成后，列表自动收拢回 Star；
- AI 工作期间，编辑区传达“正在处理”的状态，而不以额外浮窗抢占注意力；
- 视觉延续 MeetFlow 的绿灰色、紧凑排版与低饱和层次；
- 现有任务提交、轮询、结果写回当前编辑框、错误提示和人工保存流程保持不变。

当前适用的编辑块包括会议纪要、项目进展、决策、行动项和开放问题。新增注册到编辑器助手槽位的 AI 动作也必须自动获得相同的容器行为。

## 用户流程

1. 用户在编辑器标题栏点击 Star。
2. Star 下方展开紧凑菜单。菜单标题表明当前 AI 用途；菜单仅展示该编辑块注册的二到三个操作。主操作使用浅绿色强调，其他操作保持中性。
3. 用户点击某一操作。菜单立即关闭，Star 保持强调状态，当前编辑器进入忙碌状态。
4. 忙碌期间，编辑内容上方出现不改变布局的施工遮罩：内容轻度虚化、低对比度斜纹缓慢移动，底部有一条细施工轨和当前动作的语义状态文案，例如“正在生成决策建议”。没有“处理中”小浮窗，也不在内容中央放置卡片。
5. 任务成功后，遮罩淡出，结果写回当前编辑框。用户仍需通过该表单原有的保存操作落库。
6. 任务失败后，遮罩消失，原内容不变，并以现有 `notice` / 错误提示路径展示错误。

用户在忙碌期间不能再次触发 Star 菜单、其他 AI 操作或编辑文本。遮罩退出后恢复正常操作。

## 组件职责

### `PluginEditorSlot`

`PluginEditorSlot` 继续作为唯一的通用宿主，负责：

- 维护 Star 菜单的展开状态；
- 接收插件组件发出的 `update:busy` 状态；
- 在忙碌开始时关闭菜单；
- 向编辑器 slot 传递禁用状态；
- 渲染统一的施工遮罩、状态文案和可访问性状态；
- 为当前激活动作提供容器层的样式钩子。

它不识别“决策”“行动项”等业务类型，也不负责提交任务或解释 AI 结果。

### AI 工作插件

`plugins/ai-work-assistant/frontend/assistant-ui.js` 保留每个动作的 `label`、`busyLabel` 和任务调用逻辑。它负责提供适合菜单展示的操作内容，以及开始和结束时的忙碌事件。

插件按钮不再依赖通用的 `button button-quiet` 外观。每一项使用专用的菜单操作类，使动作名称、主操作强调和可选短说明可以由容器稳定排版。动作本身仍由插件注册，因此未来插件无需复制宿主的忙碌 UI。

## 视觉规范

### Star 与操作菜单

- 编辑器工具栏维持现有高度和标签位置；Star 是唯一的 AI 入口。
- 默认 Star 使用浅绿背景和深绿图标；菜单开启或任务运行时使用实心深绿背景，避免增加额外旋转图标。
- 菜单右对齐 Star，使用白色表面、细边框、11px 圆角和柔和阴影。
- 菜单头部展示用途，例如“AI 协助决策”，并以小型浅绿色标签标示“当前编辑块”。
- 菜单操作行带简洁 Star 标记。首项为浅绿背景；hover / keyboard focus 增加更浅的绿色底色与清晰焦点环。
- 字体继承应用的 UI 字体栈；标题和操作名使用 12–13px，中性说明使用 10–11px。不得混入聊天气泡、渐变文字或高饱和紫蓝色。

### AI 施工遮罩

- 遮罩覆盖编辑内容区域，不覆盖页面其他内容，也不改变编辑器高度。
- 基层是半透明的绿白表面，使用约 1.5–2px 的背景虚化；底层文本仍能辨认，避免“内容被锁死”的压迫感。
- 斜纹为约 3px 的低透明度绿色线条，间隔宽、速度慢（约 2.4 秒完成一个平移周期），呈现持续工作感而非加载错误或警示带。
- 遮罩底部使用一条细分隔线与小型移动施工轨。轨道使用深绿与浅绿相间的短斜纹，约 0.65 秒平移一次。
- 状态文案与施工轨在同一行，采用 11px、半粗的产品文字颜色。可保留“请稍候”这类低权重辅助文字，但不显示独立的“处理中”胶囊、浮窗或居中卡片。
- 动画必须尊重 `prefers-reduced-motion`：减少动态时固定斜纹与施工轨，仅保留轻度色彩提示。

### 响应式与层级

- 菜单在窄屏仍右对齐触发点，最大宽度不超过可用编辑器宽度；菜单内容允许正常换行，不被裁切。
- Star、菜单和施工遮罩仅使用编辑器槽位内部的定位层级，不得遮挡相邻表单控件或其它编辑器。
- Escape 仍可关闭未开始任务的菜单；开始任务后菜单已关闭，因此 Escape 不会取消后台任务。

## 状态与错误处理

`busy.active` 是渲染施工态的唯一信号。动作开始时，插件先发出带语义 `busyLabel` 的活动状态，再创建和轮询任务；无论请求成功、失败或发生异常，`finally` 都恢复非活动状态。

写入结果前先关闭菜单；如果编辑器 writer 尚未就绪，继续通过现有 `notice` 提示并保证忙碌态恢复。失败不覆盖 `modelValue`，成功只更新当前编辑器的草稿值，不创建结果实体、不自动保存表单。

施工态使用 `role="status"` 和 `aria-live="polite"`。Star 应正确反映 `aria-expanded`，并在忙碌时禁用且保留可读的 AI 工具名称。菜单操作保留原生 button 语义与键盘焦点。

## 测试与验收

在现有 `plugin-editor-slot` 和 AI 工作插件测试基础上增加或调整以下覆盖：

1. 打开 Star 后显示当前槽位的操作菜单与对应动作；不同编辑块仍只展示各自注册的动作。
2. 点击动作会提交原有任务、立即关闭菜单，并将 Star 和编辑器置为忙碌状态。
3. 忙碌态渲染统一施工遮罩、语义 `busyLabel` 和状态可访问性属性；不渲染独立“处理中”浮窗。
4. 忙碌时 Star、菜单动作与编辑器输入均不可再次操作；任务结束后恢复。
5. 成功仅写回当前编辑器草稿；失败保留原文并显示已有错误提示。
6. 组件样式或 DOM 断言确认菜单与遮罩使用新的专用类；必要时添加 `data-testid`，不以易变的完整 CSS 文本作为断言目标。
7. 运行前端测试和生产构建；后端任务接口没有修改，不以本次 UI 改动为理由改变其契约。

## 实施边界

优先在 `frontend/src/components/PluginEditorSlot.vue` 和 `plugins/ai-work-assistant/frontend/assistant-ui.js` 完成宿主和动作外观调整，并在相邻前端测试中验证。全局样式只在需要跨作用域共享 token 时补充；不重构任务系统、不改变插件注册 API、不为每个编辑块编写重复 UI。
