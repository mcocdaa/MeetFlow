# PR #2 审查修复设计

**日期：** 2026-07-31  
**状态：** 已确认，待实施

## 目标

修复会议系列工作流中会造成数据丢失、周期实例状态错误、调度不可用、跨项目写入、数据库迁移漂移或时区错误的问题，并用回归测试固化这些契约。

## 范围

### 数据与会议生命周期

- 议题“完成并进入下一项”先同步编辑器并保存脏草稿；保存或版本冲突失败时不改变议题状态。
- 已取消会议拥有独立列表分组，状态筛选结果必须可见。
- 启动固定周期实例时，关闭同一系列中所有更早且未结束的固定实例。
- 派生的决策、行动和开放问题保持来源议题所有权；议题迁移、编辑和删除不得破坏来源同步或级联删除。
- 所有实际耗时计算复用议题生命周期函数；测试通过生命周期而非直接写字段验证耗时。

### 周期物化与调度

- 周期规则只在有限历史窗口内回填，避免旧锚点批量创建无限历史会议。
- 请求路径的补算限制在当前项目；后台调度器可以继续处理全局到期系列。
- 调度循环在线程中运行同步数据库工作，捕获单次失败后继续下一轮，并正确传播取消。
- 每个系列物化时一次查询已有槽位，保留唯一约束处理并发竞争。

### 迁移、时区与契约

- `0007` 的枚举类型和临时默认值与 ORM 对齐；回填后移除服务器默认值，并让迁移基线测试比较类型、约束和默认值。
- 系列锚点日期使用浏览器本地日期，前端请求测试必须断言其存在。
- 周期规则把内部断言升级为明确验证错误；DST 策略用注释固定。
- AI 插件上下文文档列出稳定字段，便于插件兼容。

## 非范围

- 不改变既有会议系列数据模型、用户工作流或 UI 布局。
- 不引入外部调度服务、队列或新容器。
- 不单独处理纯维护性意见：返回类型标注、状态标签去重、`SeriesStatus` 收窄、路由 query 重构、Markdown 格式和通用函数抽取；它们不影响本次运行时契约。

## 失败与一致性策略

议题完成以“保存成功后才可完成”为原子顺序；保存失败返回原错误并保持编辑状态。周期槽位的唯一约束仍是并发最后防线，批量查找仅减少正常路径的数据库往返。调度器记录并吞掉非取消异常，避免单次数据库错误永久关闭周期实例创建。

派生产出只由来源议题的标签同步拥有。通用议题迁移遇到派生产出时不得把它转成普通产出；任何迁移必须同时迁移其来源或跳过该行，确保后续标签保存和级联删除仍以同一来源为准。

## 验证

- 后端：周期回填上限、项目隔离、全部历史实例收尾、调度器异常恢复、迁移结构一致性、派生产出来源链和实际时长。
- 前端：完成前保存、已取消分组、本地锚点日期和提交载荷。
- 全量：`.venv/bin/python -m pytest -q`、`npm --prefix frontend test`、`npm --prefix frontend run build`、`python -m pytest -q backend/tests/test_release_workflow.py`、`git diff --check`。
