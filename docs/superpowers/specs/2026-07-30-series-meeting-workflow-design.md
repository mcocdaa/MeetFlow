# 会议系列、议题流程与会后档案设计

**日期：** 2026-07-30
**状态：** 已确认，待实施计划

## 目标

让 MeetFlow 的会议系列成为可执行的排期能力；简化会议启动与收尾；让议题、纪要和产出形成清晰的单向关系，并在不重绘现有双栏 Meeting Workbench 的前提下改善状态感知与操作反馈。

## 范围

- 可执行的系列排期：每天、每周、每月、每年，系列级时区可选。
- 固定周期会议的自动创建、补算与上一固定周期未结束会议的自动收尾。
- 待开始、会议进行中、已结束的用户可见会议流程。
- 议题预计时长、实际耗时、队列状态和会议结束时的统一跳过。
- 议题记录标签生成产出，且与手动产出严格隔离。
- 显式保存会议纪要，以及会后摘要对纪要和议题记录的完整展示。
- 基于当前双栏工作台的视觉与交互修正。

不包含：外部 Cron、独立调度容器、Redis、会议纪要标签解析、AI 直接写入数据库、议题历史版本。

## 系列与周期实例

`MeetingSeries` 从仅有 `recurrence_description` 的说明性模型扩展为结构化规则：`recurrence_frequency`、`recurrence_interval`、`recurrence_weekday`、`recurrence_month_day`、`recurrence_month`、`recurrence_local_time`、`recurrence_timezone`、`recurrence_anchor_date` 和默认会议时长。界面从这些字段生成可读的周期说明；说明文本不再是调度依据。

固定周期与临时实例都保留 `series_id`。`Meeting` 增加 `occurrence_kind`（`scheduled` 或 `manual`）和可空的 `series_slot_at`；固定周期实例在 `series_slot_at` 保存该周期的 UTC 开始时刻，临时实例不占用周期槽位，因此不会替代该系列下一个固定周期会议。数据库对“系列 + 固定周期槽位”建立唯一约束，确保多次轮询、重启和补算不会生成重复会议。

每月日期超过该月最后一天时，在该月最后一天创建实例。例如，设为每月 31 日的系列在二月生成于二月最后一天。

应用进程内新增低频异步排期 worker，每分钟检查到期系列并创建“待开始”会议。它不调用 AI，也不需要额外容器或外部服务。用户打开系列、会议列表或开始固定周期会议时执行同一套补算逻辑，弥补服务停机期间错过的轮询。

点击开始某个固定周期会议时，服务先查找同一系列的上一固定周期实例；若它未结束，则按普通结束会议的规则收尾。临时实例不参与这一“上一周期”判定。暂停系列后不再创建新固定实例，历史和临时实例保持可见。

## 会议与议题状态

新会议的用户可见流程为：待开始、会议进行中、已结束。现有 `ready` 数据保持兼容并可直接开始，但新流程不再要求或展示“准备完成 → 开始会议”的两步操作。

开始会议前，前端先保存当前会议与议题草稿；成功后会议直接进入进行中，并选择第一个未完成议题。开始议题记录开始时间；完成议题记录结束时间和持久化的 `actual_duration_seconds`。议题新增时默认预计时长为 5 分钟。

结束会议始终允许执行，不因待讨论议题而禁用或报错。在同一事务中，所有 `planned` 与 `in_progress` 议题改为已跳过，并写入结束时间和实际耗时，然后会议保存为已结束并生成完成快照。未开始即被跳过的议题实际耗时为 0；已经开始的议题使用结束时刻减开始时刻。

议题并发控制继续使用每个 `AgendaItem` 自己的 `version`，用于保存、开始与结束请求。会议版本仅用于会议级字段和队列排序。议题详情不再向用户显示内部“版本 N”，因为新建议题都从版本 1 开始且该信息没有操作价值。

## 议题记录与产出

只在单个议题记录中解析以下独占行：

```text
@决策: 内容
@行动: 内容
@开放问题: 内容
```

保存议题时先解析全部标签。标签内容为空或格式不完整时，整个保存返回验证错误，不保存议题文本也不写入产出。解析、议题保存和自动产出同步在一个数据库事务内完成。

`Decision`、`ActionItem` 与 `OpenQuestion` 分别增加可空的 `source_agenda_item_id` 和 `source_tag_key`。自动产出将这两个字段写为来源议题和“标签类型:同类型序号”；每张产出表对这两个来源字段建立唯一约束。再次保存时按来源字段更新自动产出，避免重复创建；删除标签会删除对应自动产出。自动产出在下方显示“来自议题记录”，不能在产出编辑器单独修改；修改必须回到原标签行。

用户从下方“添加决策/行动/开放问题”创建的产出不带来源标记，永远不被议题记录的保存、标签修改或标签删除影响。会议级纪要也不会解析标签，更不会创建或删除产出。

AI 插件使用服务端构造的可信上下文。议题相关操作的上下文包含标签语法、当前议题记录、自动与手动产出、议题状态、预计/实际时长、会议参与者和已保存纪要。AI 只返回可审阅、可编辑的建议；没有直接写入会议、议题或产出的权限。

## 纪要、快照与会后展示

会议级纪要提供独立的“保存纪要”按钮和可见的保存状态，不再仅在会议切换生命周期时被动保存。完成会议的快照包含已保存纪要、每个议题的记录正文、最终状态、预计/实际时长以及自动和手动产出。

会后页面在现有完成链条中展示会议纪要，并按议题展示记录正文、状态、预计/实际时长和全部产出。快照页面只读展示冻结内容；重新打开会议后再次结束会生成新的完成快照。

## 当前双栏工作台 UI

保留 `AgendaWorkbench` 的左侧议题详情和右侧议题队列，不创建另一套会议页面。

- 左侧标题固定为 `Current topic`。空态顶部对齐，并显示“还没有议题”和引导文字，和右侧队列顶部对齐。
- 右侧添加议题表单增加预计时长，默认 5 分钟。队列用中文显示待讨论、当前讨论、已完成和已跳过，并显示预计/实际时长及产出来源提示。
- 点击队列议题时，仅左侧详情以 180ms 的淡入和轻微位移过渡；右侧继续以选中边框标识当前详情。系统遵从 `prefers-reduced-motion`，此时不播放过渡。
- 会议进行中时，既有工作区增加状态条、当前议题和用时强调，以及极浅的工作区背景区分；不改变双栏结构。
- 删除所有议题级跳过入口。结束会议按钮始终可用。
- 基础 `.button` 统一提供 hover 阴影/轻微抬升、active 按压反馈、键盘焦点环和禁用态。保存议题与保存纪要使用同一组件样式。

## 数据迁移与兼容性

生产数据结构变更通过 Alembic 迁移完成。迁移新增系列排期字段、`Meeting.occurrence_kind` 与 `Meeting.series_slot_at`、`AgendaItem.actual_duration_seconds`，以及三张产出表各自的来源议题和来源标签字段。现有非系列会议、已有系列和手动产出保持原样；旧 `ready` 会议可直接通过新的开始操作进入进行中。

## 验证

- 后端：系列排期、时区、短月规则、worker 幂等性与补算、上一周期收尾、议题耗时、结束会议统一跳过、标签同步、手动产出隔离、快照内容和独立并发版本。
- 前端：新增议题默认时长、直接开始会议、无跳过入口、保存纪要、队列状态、空态对齐、议题切换、按钮状态和会后内容展示。
- 集成：隔离容器中创建系列、等待或模拟到期、生成待开始实例、开始下一固定周期、重新加载后核对收尾快照和 AI 插件上下文。
- 常规命令：`.venv/bin/python -m pytest -q`、`npm --prefix frontend test`、`npm --prefix frontend run build`。
