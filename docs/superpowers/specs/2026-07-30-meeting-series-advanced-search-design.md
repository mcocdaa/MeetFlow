# 会议列表高级搜索设计

## 背景与目标

会议列表目前只有关键词和项目选择器。通过项目页的会议系列链接进入列表时，URL 会带有 `series_id`，但该条件仅以一个普通标签显示：它既不属于清晰的筛选界面，也无法让普通用户发现或主动使用系列筛选。

本次调整采用渐进展开的高级搜索。默认列表保持紧凑；用户需要时可见地打开高级条件；从会议系列进入时，页面直接说明筛选已经生效。

## 交互与视觉

1. 关键词搜索框右侧始终显示“高级筛选”按钮。没有生效条件时，它是中性的次级按钮。
2. 点击按钮展开或收起高级筛选面板。面板由项目、会议系列、会议状态三个选择器组成，默认值均为“全部”。
3. 有任一高级条件时，按钮显示数量徽标并使用激活色；展开面板显示“高级筛选”和“已启用 N 项”。
4. 从 `?series_id=...` 进入时，系列选择器自动取该值，面板默认展开，并突出该系列作为已生效条件。用户不需要知道 URL 参数的存在。
5. 面板底部显示当前筛选结果的数量；提供“清除全部”，系列条件也可在选择器内恢复为“全部”。清除系列条件时同步移除 URL 的 `series_id`。
6. 窄屏下，工具栏和面板改为单列；高级筛选按钮不被关键词框挤出。

## 数据与边界

- 不修改会议 API、数据库或会议系列数据模型。
- 列表继续使用当前已加载的会议数据进行关键词、项目、系列和状态组合筛选。
- 系列的可选项从已加载会议中的关联系列去重而来；这确保筛选器只呈现当前用户可见且实际有会议记录的系列。
- `series_id` 是唯一需要写回 URL 的高级条件，以保留现有项目页系列链接和刷新后的进入语义。项目和状态是当前页面会话内的视图状态。

## 组件边界

本次保持 `MeetingsView.vue` 为单一页面级组合点：它拥有筛选状态、URL 同步和结果计算。样式以 `meeting-list-filters` 为基础扩展出高级面板与激活态，避免引入只在一个页面使用的抽象组件。

## 错误处理与可访问性

- 高级按钮使用 `aria-expanded` 和明确的可访问名称。
- 未知或已经不可见的 `series_id` 仍保留为一个可清除的已启用条件，避免用户陷入无法退出的空列表。
- 选择器均可通过键盘操作；清除全部不影响关键词搜索。

## 验证

前端测试覆盖：

1. 普通会议列表显示高级筛选入口，点击后显示三个条件。
2. 选中项目、系列或状态后，筛选结果与激活数量正确。
3. 携带 `series_id` 进入时自动展开、显示系列条件，并可清除且同步移除 URL 参数。
4. 生产构建通过；通过浏览器在实际列表页确认默认、激活和窄屏状态。
