# MeetFlow Lite 设计说明

## 1. 产品概述

MeetFlow 是一个轻量级多人会议档案工具，用于在单一共享工作区中集中保存会议记录、关键结论、行动项、图片、小文件和会后补充。

产品的核心对象不是 Markdown 文档，而是一个结构化的“会议包”（Meeting Package）。Markdown 仅用于原始记录、关键结论和会后补充等适合自由书写的区域。

第一版的产品重心为：会议档案 70%，行动项追踪 30%。它面向小团队、黑客松演示和后续部署到远程服务器的场景。所有已批准用户共享并可编辑全部会议档案。

## 2. 目标与非目标

### 2.1 目标

- 在三小时黑客松周期内优先完成可演示的端到端工作流。
- 以会议为单位保存结构化信息、Markdown 记录、行动项和附件。
- 支持在会议结束后持续追加进展。
- 支持按标题和项目查找会议。
- 汇总所有会议产生的未完成行动项。
- 提供账号登录、注册申请、管理员审批和固定体验账号创建能力。
- 提供一个所有已批准用户共享的工作区。
- 记录会议及关联内容的创建者，并记录会议的最后修改者。
- 预留可在 Docker 部署后追加的后端 Python 插件系统。
- 使用单个 Python 服务运行，并可通过单个 Docker 容器部署。
- 将运行内存保持在 2 GB 以下；正常空闲状态预计仅占用数十到数百 MB。
- 通过挂载数据目录和插件目录完成持久化与扩展。

### 2.2 第一版不做

- 多工作区、组织、团队或逐会议授权。
- 私有会议和只读成员角色。
- 实时协同编辑、内容锁定和版本冲突合并。
- 完整修改历史或审计日志。
- 内置 AI 总结、润色或会议纪要功能。
- 网页上传、安装或热加载插件代码。
- 插件前端代码注入和任意 Vue 组件加载。
- 复杂标签体系、人员通讯录和项目管理。
- 文档全文检索。
- PDF、Office 或代码文件的在线编辑。
- 服务端图片缩略图生成。
- 密码找回邮件、第三方登录和多因素认证。
- Markdown 导出、图片灯箱和文本附件在线预览；这些仅在核心功能完成后考虑。

## 3. 用户与权限模型

### 3.1 角色

- `admin`：拥有普通成员的全部权限，并可审批用户、创建固定账号、禁用账号和管理插件配置。
- `member`：可查看、创建和编辑共享工作区中的全部会议、行动项、附件和会后补充。

第一版没有逐会议权限。任何已批准成员都能编辑全部会议；同一内容被多人同时保存时，以最后一次成功保存为准。

### 3.2 账号状态

账号状态限定为：

- `pending`：已提交注册申请，不能进入工作区。
- `active`：已获批准，可以登录和使用工作区。
- `rejected`：注册申请被拒绝，不能登录。
- `disabled`：账号被管理员停用，不能登录。

### 3.3 管理员初始化

首次启动从环境变量读取：

```env
ADMIN_USERNAME=admin
ADMIN_PASSWORD=replace-with-a-strong-password
APP_SECRET_KEY=replace-with-a-long-random-secret
ALLOW_REGISTRATION=true
```

- 首次启动时创建一个 `active` 状态的管理员账号。
- 后续启动不会使用环境变量覆盖现有管理员密码。
- 用户名按小写形式规范化并保持唯一，显示名称可保留原始大小写。
- 生产模式要求管理员初始密码至少 12 个字符、`APP_SECRET_KEY` 至少 32 个随机字符；缺失或不满足长度要求时拒绝启动。
- `.env` 不进入版本控制，只提供不含真实密钥的 `.env.example`。

### 3.4 注册与固定体验账号

- `ALLOW_REGISTRATION=true` 时，未登录访客可提交用户名、显示名称和密码，账号进入 `pending`。
- 管理员可批准、拒绝或禁用账号。
- 管理员可直接创建 `active` 成员账号，用于固定体验账号或内部成员。
- 用户可修改自己的密码，管理员可为成员重置密码；修改或重置后，旧登录 Cookie 立即失效。
- `ALLOW_REGISTRATION=false` 时隐藏注册入口并拒绝注册 API；已有账号仍可登录。
- 多人共用固定体验账号时，系统只能将操作归因于该共享账号，这是明确接受的限制。

## 4. 核心工作流

```text
注册申请或管理员创建账号
   ↓
管理员批准
   ↓
用户登录共享工作区
   ↓
创建会议并填写基本信息
   ↓
手动记录并整理关键结论
   ↓
添加行动项和附件
   ↓
会后持续补充进展
   ↓
从首页检索档案或从待办页追踪行动项
```

演示流程如下：

1. 使用管理员预先创建的固定体验账号登录。
2. 创建“黑客松产品讨论”会议。
3. 填写项目、类型、时间和参与人。
4. 写入数行 Markdown 原始记录并整理关键结论。
5. 创建两个行动项。
6. 上传一张白板图片和一个 PDF。
7. 返回首页，通过项目或标题找到会议。
8. 打开待办页，查看来自不同会议的未完成行动项。
9. 管理员打开用户管理和插件管理页面，展示审批与可扩展能力。

## 5. 信息架构与页面

### 5.1 登录与注册

- 登录页提供用户名和密码输入。
- 允许注册时显示注册入口。
- 注册成功后明确显示“等待管理员批准”，不自动登录。
- 待审批、拒绝和禁用账号收到不同的可理解提示，但登录失败不得泄露其他账号是否存在。

### 5.2 首页

首页按会议时间倒序显示会议卡片，而不是普通文档列表。每张卡片显示：

- 标题、会议时间和项目。
- 会议类型和参与人摘要。
- 关键结论、行动项和附件数量。
- 未完成行动项数量。
- 创建者及最后修改者。

首页提供创建会议、按标题和项目进行包含匹配的搜索框，以及进入全部未完成行动项的入口。

### 5.3 会议详情页

会议详情分为五个清晰区域：

1. **概览**：基本信息、关键结论、待完成行动项和附件摘要。
2. **会议记录**：原始 Markdown 记录和独立保存的关键结论。
3. **行动项**：行动内容、负责人、截止日期和状态。
4. **附件**：图片缩略展示，以及普通文件的上传、下载和删除。
5. **后续补充**：按创建时间追加 Markdown 记录，并显示作者。

详情页支持编辑会议基本信息和删除会议。删除完整会议前必须二次确认。

若插件注册了会议动作，详情页显示由核心前端渲染的通用动作按钮。动作结果先显示为可编辑草稿，未经用户确认不得覆盖正式会议内容。

### 5.4 待办页

待办页汇总所有会议中尚未完成的行动项，并显示来源会议、负责人、截止日期和创建者。用户可直接更新状态或进入来源会议。

### 5.5 管理员页面

普通成员看不到管理员导航，也不能访问管理员 API。

- **用户管理**：查看待审批和现有账号，批准、拒绝、禁用账号，直接创建固定体验账号。
- **插件管理**：查看已发现插件、版本、启用状态、加载错误和配置表单。敏感配置只显示是否已设置。

## 6. 技术架构

MeetFlow 采用单体轻量架构：

- **前端**：Vue 3 + Vite，使用原生 CSS，不引入大型 UI 组件库。
- **后端**：FastAPI，由单个 Uvicorn 进程运行。
- **数据库**：SQLite 单文件，不运行独立数据库服务。
- **附件存储**：本地文件系统，数据库仅保存元数据和相对路径。
- **插件目录**：只读挂载的后端 Python 插件目录，应用启动时发现并加载。
- **生产部署**：前端构建为静态文件后由 FastAPI 提供，生产环境不运行 Node.js 服务。
- **容器化**：一个 Docker 镜像、一个容器、一个数据目录和一个插件目录。

```text
Browser
   ↓
Vue 单页应用
   ↓ /api
FastAPI / Uvicorn
   ├── Auth：登录、注册与管理员审批
   ├── Meetings：共享会议档案
   ├── Plugin Registry：发现并调用可信插件
   ├── SQLite：业务数据、用户、插件状态与配置
   ├── /app/data/uploads/：图片和小文件
   └── /app/plugins/：外部插件代码（只读）
```

后端保持与 KnowFlow、HarvestFlow、AutoFlow 相似的清晰职责划分，但不复制 Redux、MongoDB 或复杂通用 Hook 系统。插件扩展范围被限制为明确的注册契约。

## 7. 模块边界

### 7.1 前端

- `auth`：登录、注册和当前用户状态。
- `meetings`：会议列表、详情、创建、编辑和删除。
- `actions`：会议内行动项编辑及跨会议汇总。
- `attachments`：上传、下载、删除和图片展示。
- `updates`：会后补充记录。
- `admin/users`：用户审批、禁用和固定账号创建。
- `admin/plugins`：插件状态和配置表单。
- `plugin-actions`：通用会议动作按钮、运行状态和草稿结果面板。
- `api`：HTTP 请求、响应解析和统一错误处理。

### 7.2 后端

- `api`：请求校验、认证依赖、角色校验、HTTP 状态码和响应模型。
- `services`：账号审批、会议删除、附件上传和插件动作调用等跨资源流程。
- `repositories`：SQLite 数据读写，不包含 HTTP 或文件展示逻辑。
- `storage`：附件路径生成、写入、读取和删除。
- `auth`：密码哈希、Cookie 签名和当前用户解析。
- `plugins`：清单校验、插件发现、注册表、加载错误隔离和动作调用。
- `secrets`：从主密钥派生加密密钥，负责插件敏感配置的加解密。
- `config`：数据目录、插件目录、上传大小、管理员初始化和服务配置。

API 路由不直接拼接磁盘路径，数据库仓库不负责删除文件，业务模块不直接导入具体插件实现。

### 8.2 meetings

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT | UUID 主键 |

| updated_by | TEXT | 最后修改者用户外键 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 最后更新时间 |

第一版不建立人员表、项目表和会议类型表。项目及类型使用普通文本，前端可以从历史会议中提取已有值作为输入建议。

### 8.3 action_items

| 字段 | 类型 | 说明 |

| id | TEXT | UUID 主键 |

| owner | TEXT | 可选负责人名称 |

| updated_at | DATETIME | 最后更新时间 |

`owner` 是自由文本，不强制对应系统用户，因为行动项可能属于未注册参会人。

### 8.4 attachments

| created_by | TEXT | 上传者用户外键 |
| created_at | DATETIME | 上传时间 |

### 8.5 meeting_updates

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT | UUID 主键 |

### 8.6 plugin_states

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| plugin_id | TEXT | 插件清单中的唯一 ID |
| enabled | BOOLEAN | 管理员设置的启用状态 |

| updated_at | DATETIME | 最后更新时间 |

插件目录中的 `plugins.yaml` 提供初始启用状态；SQLite 中的状态一旦存在即覆盖清单默认值。启停变更在下次容器启动时生效。

### 8.7 plugin_configs

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| plugin_id | TEXT | 插件 ID |
| config_key | TEXT | 配置项名称 |
| stored_value | TEXT | JSON 编码的普通值或加密后的敏感值 |

| updated_by | TEXT | 最后修改配置的管理员 |
| updated_at | DATETIME | 最后更新时间 |

所有会议子表通过外键关联会议，并启用 SQLite 外键约束。删除会议时，数据库记录使用级联删除；附件磁盘清理由会议服务负责。

## 9. 文件存储

本地测试和远程 Docker 使用相同布局：

```text
data/
├── meetflow.db
└── uploads/
    └── <meeting-id>/
        └── <uuid>.<ext>
```

文件规则如下：

- 单个文件最大 20 MB。
- 第一版接受图片和普通小文件，不维护复杂扩展名白名单。只有 JPEG、PNG、GIF 和 WebP 可作为图片内联展示；SVG、HTML、脚本及其他文件始终作为下载附件返回。
- 磁盘文件名使用服务端 UUID，原文件名仅用于展示和下载响应。
- 存储路径由服务端生成，并验证最终路径位于该会议目录内，防止路径穿越。
- 图片由浏览器通过受控附件接口加载，并使用 CSS 生成视觉缩略图，不创建额外缩略图文件。
- 上传时先写入临时文件，完成大小校验后原子移动到目标位置，再写入数据库记录。
- 若数据库写入失败，删除已移动的文件。
- 删除附件时先确认归属，删除数据库记录后再删除磁盘文件；磁盘文件不存在时仍将数据库删除视为成功并记录警告。
- 删除会议时，数据库事务完成后清理对应附件目录；清理失败需记录错误，但不恢复已经删除的会议数据。

## 10. 插件系统

### 10.1 安装与加载边界

第一版只支持服务器管理员通过宿主机复制或挂载插件目录，然后重启容器。网页不能上传、安装或执行新的插件代码。

```text
plugins/
├── plugins.yaml
└── ai-summary/
    ├── plugin.yaml
    └── backend.py
```

- `/app/plugins` 在容器中以只读方式挂载。
- 插件管理查询可以重新扫描 `plugins.yaml` 和各插件 `plugin.yaml`，但只读取和校验清单，绝不在请求过程中导入代码。
- 应用启动时只导入已启用且清单有效的插件代码。
- 单个插件加载失败只记录为该插件的错误，不阻止 MeetFlow 启动。
- 新增插件、替换插件代码或切换启用状态后需要重启容器。
- 插件是管理员安装的可信 Python 代码，与主应用具有相同的进程、文件和网络权限，不提供沙箱隔离。

### 10.2 插件清单

插件清单至少声明：

```yaml
id: ai-summary
name: AI Meeting Summary
version: 0.1.0
api_version: 1
backend_entry: backend.py
description: Generate meeting summaries through an OpenAI-compatible API
config_schema:
  fields:
    - key: base_url
      type: string
      required: true
    - key: model
      type: string
      required: true
  secrets:
    - key: api_key
      required: true
```

清单未知字段可以忽略，但缺少必填字段、ID 不合法或 API 版本不兼容时不得导入代码。

### 10.3 注册契约

后端入口统一导出：

```python
def register(registry):
    registry.register_meeting_action(...)
```

会议动作必须声明：

- 全局唯一 `action_id`，形式为 `<plugin_id>.<action_name>`。
- 按钮名称和说明。
- 是否仅管理员可执行。
- 输入配置 Schema 和输出结果 Schema。
- 异步处理函数。

核心调用插件时提供只读的会议上下文：会议基本信息、原始记录、关键结论、当前行动项、会后补充、附件元数据和当前用户。第一版不向插件传递附件二进制内容。

核心系统负责登录校验、会议查询、上下文构造、调用超时和统一错误响应。插件动作可以返回 Markdown 草稿和标准化的 `suggested_patch`；核心前端展示并允许用户编辑，用户确认后再通过现有会议更新接口保存。用户确认前，插件不得直接修改正式会议数据。

插件配置通过受控对象传入处理函数。敏感值不会出现在会议上下文、日志或管理 API 响应中。

### 10.4 通用前端集成

第一版插件不能注入前端代码。核心前端通过动作发现接口获取按钮元数据，通过统一执行接口调用动作，并以通用 JSON/Markdown 结果面板显示草稿。

未来 AI 会议总结插件可以注册“生成会议纪要”动作，使用管理员网页配置的 API 地址、模型和 API Key，而无需重新构建 MeetFlow 前端。

## 12. 认证、配置与安全边界

- 密码使用 Argon2 哈希，绝不保存明文。
- 登录成功后设置最长有效期为 7 天的签名 `HttpOnly` Cookie，其中只保存用户 ID、会话版本和过期时间；每个受保护请求仍查询用户状态和会话版本，确保禁用或改密立即生效。
- 生产 Cookie 启用 `Secure` 和严格的 SameSite 策略。
- 生产部署使用同源前后端并校验状态变更请求的 Origin，不开放宽泛 CORS。
- `APP_SECRET_KEY` 通过密钥派生生成相互独立的 Cookie 签名密钥和插件配置加密密钥。
- `APP_SECRET_KEY` 在同一数据目录的生命周期内必须保持不变；直接更换会使现有 Cookie 和已保存插件密钥失效，后续如需轮换必须提供显式迁移流程。
- API Key 等敏感插件配置加密后存入 SQLite；管理员页面只显示“已配置”，只能替换或清除，不能读取原值。
- 普通成员无法访问用户管理、插件管理或敏感配置。
- Markdown 渲染禁用或清理原始 HTML，避免存储型 XSS。
- 下载响应设置安全的 `Content-Disposition`，普通文件不以内联 HTML 执行。
- 插件清单在导入 Python 代码之前完成路径、ID 和版本校验；入口路径必须位于对应插件目录内。
- 远程部署必须启用 HTTPS，建议由 Caddy 或 Nginx 反向代理终止 TLS。

后端统一错误结构：

```json
{
  "error": {
    "code": "attachment_too_large",
    "message": "单个附件不能超过 20 MB"
  }
}
```

- 缺少标题、会议时间或行动内容时返回 422，并指出具体字段。
- 未登录返回 401，权限不足返回 403。
- 资源不存在或子资源不属于指定会议时返回 404。
- 文件超限返回 413。
- 数据库、磁盘或插件故障返回统一错误，响应中不泄露路径、SQL、密钥或堆栈。
- 前端提交失败时保留未提交内容，并显示可重试提示。
- 插件超时或失败不得写入会议数据，也不得影响其他插件和核心请求。

## 13. Docker 与远程部署

生产镜像采用多阶段构建：Node 阶段构建 Vue 静态资源，Python 阶段安装后端依赖并复制前端产物。运行时只有 Python 和应用文件。

容器约定：

- FastAPI 监听 `0.0.0.0:8000`。
- `/app/data` 为可读写持久化目录，保存 SQLite 和附件。
- `/app/plugins` 为只读插件目录，可在宿主机追加或更新插件。
- 启动时自动创建数据库、表和上传目录，并执行幂等管理员初始化。
- 提供 `/api/health` 供 Docker 或反向代理进行健康检查。
- SQLite 使用 WAL 模式和合理的 busy timeout，以适应小团队低并发读写。
- 使用单进程 Uvicorn，避免多个进程同时执行初始化和本地文件操作。

示例挂载关系：

```text
./data    → /app/data       读写
./plugins → /app/plugins    只读
```

新增插件的运维流程为：将插件目录和注册项复制到宿主机 `./plugins`，在管理员页面配置并启用插件，然后重启容器。插件加载失败时可在管理员插件页查看错误，核心会议功能仍可使用。

本地开发可分别运行 Vite 和 FastAPI 以支持热更新；部署构建必须验证由 FastAPI 正确返回前端路由和静态资源。

## 14. 测试与验收

### 14.1 认证与权限

- 首次启动创建管理员，重复启动不会覆盖管理员密码。
- 注册开启和关闭行为符合环境变量配置。
- 待审批、拒绝和禁用用户不能进入工作区。
- 管理员可批准、拒绝、禁用和直接创建固定账号。
- 用户改密或管理员重置密码后，旧 Cookie 立即失效。
- 普通成员不能访问管理员页面或 API。
- 禁用已登录用户后，其后续受保护请求立即失败。

### 14.2 会议档案

- 会议创建、读取、更新、删除及标题/项目搜索。
- 会议详情完整返回行动项、附件元数据和补充记录。
- 创建者和最后修改者归因正确。
- 行动项创建、编辑、删除和跨会议状态筛选。
- 合法附件上传、下载和删除。
- 超过 20 MB 的附件被拒绝，且不残留文件或数据库记录。
- 删除会议会级联删除子记录并清理附件目录。
- Markdown 渲染不执行危险 HTML。

### 14.3 插件系统

- 空插件目录和无注册项时应用正常启动。
- 无效清单、路径穿越和 API 版本不兼容的插件被拒绝。
- 单个插件导入失败不会阻止应用启动。
- 使用测试插件验证动作注册、发现、权限检查、调用、超时和异常处理。
- 启停状态在 SQLite 中持久化，并在下次启动生效。
- 普通配置可读取，敏感配置加密保存且所有 API 响应脱敏。
- 插件动作失败不会修改会议数据。

### 14.4 Docker 验收

1. 成功构建单个镜像并启动一个容器。
2. 使用管理员账号登录并创建固定体验账号。
3. 创建包含行动项和附件的会议。
4. 停止并重新创建容器。
5. 使用同一 `/app/data` 挂载后，用户、会议、附件和插件配置仍然存在。
6. 挂载测试插件并重启后，插件动作可被发现和调用。
7. 在受限为 2 GB 内存的环境中完成核心演示流程。

## 15. 三小时实施优先级

1. 认证、管理员初始化、共享工作区和会议 CRUD。
2. 原始记录、关键结论、行动项和附件。
3. 注册审批、用户管理和固定体验账号创建。
4. 最小插件清单、注册表和通用会议动作接口。
5. 管理员插件列表、状态与配置页。
6. Docker 双目录挂载及持久化验证。
7. 搜索、会后补充和视觉完善。

若时间不足，按顺序舍弃：文本附件预览、图片灯箱、会后补充、复杂视觉效果。认证与审批、共享会议档案、结论、行动项、附件、插件注册契约和单容器部署是第一版核心边界。

插件内核必须由一个仅用于自动化测试的最小测试插件验证，但生产镜像不内置 AI 插件。

## 16. 后续 AI 插件

AI 插件在第一版 Docker 部署完成后独立开发和挂载，不属于第一版交付内容。

预期插件通过管理员页面配置 OpenAI 兼容 API 的 Base URL、模型名和 API Key，注册“生成会议纪要/会议状态”动作。插件只使用会议文本和附件元数据，不解析附件内容；输出为可编辑草稿，由用户确认后写入关键结论或其他正式字段。

后续扩展还可以包括：

- AI 润色原始记录或建议行动项。
- 将完整会议包导出为 Markdown 或压缩包。
- 文本附件预览和图片灯箱。
- 项目、参与人和会议类型的独立管理。
- 多工作区、私有会议和更细粒度权限。
- 完整修改历史和冲突检测。

这些扩展必须通过独立服务或明确模块接入，不能破坏第一版会议包、行动项、附件、认证和插件注册表的核心边界。
