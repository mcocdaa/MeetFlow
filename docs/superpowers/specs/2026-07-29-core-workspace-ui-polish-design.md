# 核心工作区轻量 UI 统一设计

**日期：** 2026-07-29<br>
**状态：** 已确认，待实现

## 目标

在不改变 MeetFlow 的信息架构、数据流或视觉性格的前提下，系统整理登录后核心工作区的界面细节。成果应让页面更易扫描、卡片与控件更整齐，并把 AI 的运行状态表达得清晰但不喧宾夺主。

本轮采用“克制统一”方向：保留深蓝侧栏、浅灰工作台、白色内容卡和绿色主操作色；不进行品牌重设计，不添加渐变、装饰纹理或大面积高饱和色。

## 范围

### 包含

- 工作区侧栏及管理员导航的图标与选中态；
- “为你”首页的并列信息卡、列表和空状态；
- 项目、会议、决策、行动项、收件箱与 AI 任务等登录后核心页面的共享布局、卡片头部、列表行、按钮和控件节奏；
- 编辑器内 AI 入口和现有施工遮罩的视觉统一；
- 窄屏下的导航、双栏与控件换行；
- 键盘焦点、状态提示和减少动态效果偏好。

### 不包含

- 登录、注册及管理员页面的专项重设计；共享样式的改进可以自然作用于这些页面，但不为它们增加新布局。
- 路由、API、数据库、插件注册、AI 请求、任务轮询、结果写回、保存语义或失败恢复逻辑的改变。
- 新的产品功能、仪表盘指标、全屏加载层、聊天式 AI 窗口或全局动效系统。

## 视觉基础与共享规则

`frontend/src/styles.css` 建立有限且可复用的视觉规则，而不是继续在各组件堆叠一次性数值：

- 间距使用一致的 4/8/12/16/24/32px 节奏。页头、说明、筛选区、卡片标题和内容列表各自有稳定的间隔，说明文字不能紧贴下一栏目。
- 标准控件保持一致的高度、圆角、边框和键盘焦点；主操作、次操作和纯图标操作仅通过既有绿色、浅表面和中性文字表达层级。
- 内容卡的边框、阴影和内部留白统一。只有并列、同等级的信息卡要求等高；纵向列表、编辑器和长文本区域继续由内容撑高。
- 列表行、紧凑记录、空状态、提示和状态标记复用同一密度与文本层级。可点击行有低调的 hover 与 `:focus-visible` 反馈，不以位移、闪烁或重阴影作为默认效果。

## 侧栏与 SVG 图标

使用 `@lucide/vue` 的按需导入组件作为唯一的工作区图标来源。图标在构建期打包，不在运行时从外网加载。

- `AppSidebar` 的“为你、项目、会议、行动项、决策、收件箱、AI 任务”以及管理员导航使用语义匹配的 18–20px Lucide SVG；不再使用 `⌂`、`◇`、`▣`、`✓`、`◆`、`↙`、`✦` 等文本字符充当图标。
- 现有纯图标高频控件（关闭、更多、AI 入口等）采用同一图标尺度、可点击区域、`aria-label` 和焦点环；文字按钮不强制增加图标。
- 当前导航项使用浅层背景、白色文字和同色 SVG 突出；其他项保持较低对比度。不会加入竖向高亮条或整块鲜亮色。
- 在窄屏三列导航中，标签仍保留且与图标对齐，点击目标不得小于现有尺寸。

## 页面层级、双栏与列表

### 首页并列卡

“Priority queue / 需要关注”和“Next up / 近期会议”在桌面端是同一信息层级：

- 容器允许两张卡片纵向拉伸至相同高度，卡内内容从顶部排列；右侧内容较少时保留卡片比例，而不伪造额外数据或填充装饰。
- 950px 以下仍切换为单列，每张卡片由自己的内容高度决定。
- 该等高规则只适用于首页的这组并列信息面板，不应用到所有页面卡片。

### 页头和卡片头部

- 页面标题、摘要与首个模块之间使用统一的纵向分隔；AI 任务页的说明和任务列表必须显然属于不同层级。
- `section-heading` 采用稳定的左侧标题/辅助说明和右侧指标/操作布局。标题区与列表或表单正文之间使用固定间距；窄屏时右侧操作自然换行且不挤压标题。
- 项目、会议、决策、行动项和收件箱中的记录行对齐标题、元信息和尾部操作；文本溢出保持截断或自然换行的既有语义，不改变数据内容。

### 空状态与反馈

空状态沿用当前产品文案，只统一标题、说明、留白和紧凑模式的视觉密度。加载、保存、上传和刷新状态保留当前位置，不新增遮罩，也不改变原有按钮禁用条件。

## AI 入口、任务页与施工态

现有 AI 编辑器行为由 `PluginEditorSlot` 与插件动作继续管理；本轮只统一表面表现。

- 编辑器内的 Star 替换为 Lucide AI 图标。用户发起动作后，操作菜单立即收起，入口处于不可重复触发状态。
- 继续使用既有的局部施工遮罩：低对比滚动斜纹、轻微虚化、底部细施工轨和当前 `busyLabel`。遮罩仅覆盖当前编辑内容，不改变编辑器高度，不显示独立“处理中”浮窗或居中卡片。
- AI 任务页以一致的状态标记表达“排队中、生成中、已生成、已应用、已取消、未完成/可恢复失败”；保留来源回链、重新运行、取消与技术详情的原有条件和行为。
- 所有运行态使用语义状态区域和 `aria-live`；动态斜纹与施工轨遵从 `prefers-reduced-motion`，减少动态时仍保留颜色和文案提示。

## 组件边界

- `AppSidebar.vue` 只负责导航项的图标、标签和选中态；导航定义可携带图标组件或语义图标名，不承担业务状态。
- 共享 CSS 负责空间、控件、卡片、列表和响应式规则；页面组件只在需要状态标记或结构钩子时做最小模板调整。
- `HomeView.vue` 仅为首页双栏保留明确的布局钩子，不将首页等高规则泄漏到其他页面。
- `AiTasksView.vue` 只负责将已有任务状态映射到相应的状态标记和现有操作；不改任务 API。
- `PluginEditorSlot.vue` 继续是所有编辑器助手的唯一宿主，保留菜单收起、忙碌禁用、遮罩和可访问性职责；插件继续提供动作名称与 `busyLabel`。

预计改动集中在 `frontend/package.json`、`AppSidebar.vue`、`HomeView.vue`、`AiTasksView.vue`、`PluginEditorSlot.vue`、共享样式及相关前端测试。是否增设极小的共享图标组件，以现有模板可读性和按需导入效果为准；不得引入运行时图标网络依赖。

## 验收与测试

前端测试和构建需覆盖或确认：

1. 侧栏所有工作区及管理员项使用语义 SVG，并保持可访问名称、当前页状态和导航目标。
2. 首页双栏在桌面布局中可拉伸等高，在窄屏改为单列；没有把该规则推广给无关内容卡。
3. AI 任务说明、任务卡状态、错误详情和现有恢复操作仍可用；任务状态不因纯 UI 改动而改变。
4. 编辑器 AI 菜单仍按槽位展示；点击后菜单收起、编辑器忙碌、施工态含语义文案，任务结束后恢复，成功与失败的数据行为不变。
5. 纯图标控件具有名称和可见焦点；启用减少动态效果时，施工态动画不再播放。
6. 运行 `npm test` 和 `npm run build`（在 `frontend/` 目录）；必要时使用隔离容器与临时数据检查登录后的桌面及窄屏视口，且不影响当前运行服务。

## 非目标与兼容性

- 不为了视觉统一重命名 API 状态、改写 AI 任务对象或迁移 CSS 到新的设计系统。
- 不替换已确认的 AI 施工交互：菜单收起、局部遮罩、结果写回草稿和手动保存继续保持。
- 不依赖用户设备上可用的符号字体；SVG 在现代浏览器和缩放场景中保持清晰。
