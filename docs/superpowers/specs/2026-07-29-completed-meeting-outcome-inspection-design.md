# 已结束会议的议题产出回看设计

**日期：** 2026-07-29  
**状态：** 已确认，待实现

## 目标

会议结束后，用户可以在“议题与产出”中展开任一议题，直接回看该议题关联的决策、行动项和开放问题；未关联具体议题的会议级产出也应可查看。

该界面是会议完成快照的只读回放，不承担编辑、跳转或更新职责。

## 范围与约束

- 仅改进已完成会议的 `CompletedMeetingChain`。
- 所有显示数据来自 `meeting.current_snapshot.snapshot_json`，而不是 `meeting.agenda_items`、`meeting_decisions`、`meeting_actions` 或 `meeting_open_questions` 的当前值。
- 不增加 API、数据库字段或后端逻辑。
- 不为历史快照通过当前用户资料补充负责人姓名。快照只保存人员 ID，避免把会后变更的资料混入历史记录。
- 保持“添加更正”和“重新打开会议”的现有行为不变。

## 交互

### 议题手风琴

“议题与产出”中的每个快照议题渲染为独立的、默认收起的原生手风琴：

- 收起行展示议题状态、标题、决策/行动/开放问题三类计数和展开指示。
- 用户可同时展开多个议题；展开一个议题不会收起其他议题。
- 使用原生 `details` / `summary` 语义，确保鼠标、触摸、Enter 和 Space 均可操作，并由浏览器暴露正确的展开状态。
- 没有产出的议题在展开后显示“本议题未记录产出”。

### 议题内产出

展开区按固定顺序呈现有内容的分组：决策、行动项、开放问题。

- 决策显示标题、决策正文、存在时的决策依据和状态。
- 行动项显示内容、优先级、截止日期和状态。
- 开放问题显示问题正文和状态。
- Markdown 字段复用现有 `MarkdownView`，保持阅读格式一致。
- 内容均不可编辑，也没有跳转或新增操作。

### 会议级产出

若快照中的 `meeting_decisions`、`meeting_actions` 或 `meeting_open_questions` 至少有一项，则在全部议题之后渲染“会议级产出”手风琴。

- 它使用与议题相同的计数、展开和分组展示方式。
- 若三类列表均为空，则不渲染该分组，避免制造空内容。

## 视觉与响应式

- 延续完成态已有的白底、浅边框、低饱和状态色和紧凑间距。
- 收起行具有明确的整行可点击区域和不抢眼的展开箭头。
- 展开区使用轻微内嵌底色、分组标题和细分隔线建立层级；不使用抽屉、弹窗或高频动效。
- 窄屏下收起行从横向布局自然改为纵向，计数仍保持可读；展开区为单列。

## 数据边界与兼容

- 为快照 JSON 建立前端只读结构与归一化辅助逻辑；缺失的列表字段按空数组处理，以兼容早期或不完整快照。
- 仅使用快照中稳定存在的字段。不能取得冻结姓名时，不显示负责人名称。
- 页面继续兼容当前快照字段别名：`snapshot_json` 优先，`snapshot` 为后备。

## 验收与测试

前端组件测试应验证：

1. 完成会议的议题默认收起，点击后展开对应产出，且可同时展开多个议题。
2. 决策、行动项、开放问题的正文和各自关键字段正确显示。
3. 无产出议题显示只读空状态。
4. 有会议级产出时展示该手风琴；没有时不展示。
5. 渲染值来自快照，即使 `meeting` 的当前产出数据不同，也不泄漏到历史回看中。
6. 现有更正与重新打开会议的流程回归通过。

## 非目标

- 不新增会议产出的独立详情页。
- 不在完成会议中编辑、创建或迁移产出。
- 不改动后端快照格式或生命周期逻辑。
